Administração de Sistemas Proprietários

GitHub + GitHub Pages

Crie sua conta no GitHub, publique um projeto da disciplina em um repositório e transforme seu código HTML em um site acessível pela Internet.

Tutorial prático • GitHub • Repositório • GitHub Pages

🎯 Objetivos

Ao concluir este tutorial, o aluno deverá ser capaz de:

  • Criar uma conta pessoal no GitHub;
  • Verificar o endereço de e-mail da conta;
  • Criar um repositório para o projeto da disciplina;
  • Adicionar arquivos HTML, CSS e JavaScript ao repositório;
  • Ativar o GitHub Pages;
  • Acessar o projeto através de uma URL pública;
  • Atualizar o site por meio de novos commits.
Importante: o GitHub Pages é um serviço de hospedagem de sites estáticos. Ele publica arquivos como HTML, CSS e JavaScript a partir de um repositório do GitHub.

🔎 Antes de começar

Você precisará de:

  • Um computador conectado à Internet;
  • Um endereço de e-mail que você possa acessar;
  • Um navegador Web;
  • Um projeto simples da disciplina.

O GitHub recomenda a verificação do e-mail e recomenda também a configuração de autenticação de dois fatores (2FA) para aumentar a segurança da conta.

1. Criando sua conta no GitHub

1Acesse o GitHub

Abra o endereço oficial:

https://github.com/

Clique em Sign up para iniciar o cadastro.

2Informe seus dados

Siga as etapas apresentadas pelo GitHub para informar seu e-mail, criar uma senha e escolher seu nome de usuário.

Dica: escolha um nome de usuário profissional. Ele poderá fazer parte das URLs dos seus projetos.

3Verifique seu e-mail

O GitHub solicita a verificação do endereço de e-mail. Essa verificação é necessária para realizar algumas tarefas básicas, incluindo a criação de repositórios.

Concluído: depois de verificar o e-mail, sua conta estará pronta para criar o primeiro repositório.

2. Conhecendo o GitHub

ConceitoO que significa?
ContaIdentifica você dentro do GitHub.
RepositórioEspaço onde ficam os arquivos e o histórico de um projeto.
CommitRegistro de uma alteração realizada no projeto.
BranchUma linha de desenvolvimento do projeto.
GitHub PagesServiço que publica um site estático a partir de um repositório.

3. Criando o projeto da disciplina

Depois de entrar na sua conta, procure a opção para criar um novo repositório (New repository).

1Nome do repositório

Utilize um nome relacionado à disciplina. Por exemplo:

administracao-sistemas-http

Outras possibilidades:

projeto-http
atividade-iis
meu-servidor-web
sistemas-proprietarios

2Descrição

Adicione uma descrição curta, por exemplo:

Projeto prático da disciplina de Administração de Sistemas Proprietários.

3Visibilidade

Para esta atividade, utilize um repositório Public, especialmente se estiver usando uma conta gratuita do GitHub.

Atenção: não coloque senhas, tokens, chaves privadas, documentos pessoais ou qualquer informação sensível no repositório ou no site publicado.

4README

Marque a opção para adicionar um arquivo README e crie o repositório.

4. Criando o primeiro arquivo HTML

Dentro do repositório, crie um arquivo chamado:

index.html

Use este exemplo inicial:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Meu Projeto</title>
</head>
<body>
    <h1>Meu Projeto da Disciplina</h1>

    <p>Aluno: SEU NOME</p>
    <p>Disciplina: Administração de Sistemas Proprietários</p>
    <p>Tema: HTTP</p>
</body>
</html>

Adicione o arquivo ao repositório e registre a alteração com uma mensagem de commit, por exemplo:

Cria página inicial do projeto

5. Estrutura recomendada para o projeto

À medida que o projeto crescer, organize os arquivos:

administracao-sistemas-http/
│
├── index.html
├── sobre.html
├── css/
│   └── style.css
├── js/
│   └── script.js
└── imagens/
    └── servidor.png
Regra importante: os caminhos dos arquivos devem estar corretos e, para facilitar a publicação, evite espaços e caracteres especiais nos nomes dos arquivos e pastas.

6. Ativando o GitHub Pages

Agora vamos transformar o repositório em um site.

1Abra as configurações

No seu repositório, acesse:

Settings → Pages

2Configure a publicação

Na área Build and deployment, configure a fonte de publicação para utilizar uma branch do repositório.

Uma configuração simples para este projeto é:

OpçãoValor
SourceDeploy from a branch
Branchmain
Folder/(root)

Salve a configuração.

O GitHub Pages também pode utilizar fluxos de trabalho com GitHub Actions. Para uma primeira atividade, publicar diretamente a partir da branch main e da raiz do repositório é uma abordagem simples para compreender o funcionamento.

7. Acessando o site publicado

Depois da publicação, o GitHub disponibilizará uma URL para o site.

Para um site de projeto, a URL normalmente seguirá o formato:

https://SEU-USUARIO.github.io/NOME-DO-REPOSITORIO/

Por exemplo, se:

Usuário: aluno123
Repositório: administracao-sistemas-http

a URL do projeto será:

https://aluno123.github.io/administracao-sistemas-http/
Resultado esperado: a página index.html estará disponível no navegador através da URL do GitHub Pages.

8. Testando uma alteração

Agora altere o conteúdo do index.html. Por exemplo, acrescente:

<h2>Meu primeiro site publicado!</h2>
<p>Este projeto utiliza GitHub Pages.</p>

Faça um novo commit, por exemplo:

Atualiza página inicial

Depois aguarde a publicação e atualize o navegador.

Editar → Commit → Publicação → Atualizar navegador → Nova versão do site
As alterações podem levar alguns minutos para aparecer no site publicado.

9. Desafio prático

Agora você deverá criar um pequeno site relacionado ao conteúdo estudado na disciplina.

O site deverá conter, no mínimo:

  • Uma página inicial index.html;
  • Nome do aluno;
  • Nome da disciplina;
  • Nome da instituição;
  • Um título relacionado ao tema estudado;
  • Uma explicação sobre o conteúdo;
  • Uma imagem relacionada ao assunto;
  • Uma página adicional;
  • CSS para melhorar a apresentação visual;
  • Um link entre as páginas.

Sugestão de tema

HTTP e Servidores Web

O site pode apresentar:

  • O que é HTTP;
  • Diferença entre cliente e servidor;
  • O que é IIS;
  • O que é uma requisição HTTP;
  • Método GET;
  • Códigos 200 e 404;
  • Exemplo de URL;
  • Conclusão.

  • Conta do GitHub criada.
  • E-mail do GitHub verificado.
  • Repositório criado.
  • Repositório configurado como público.
  • Arquivo index.html criado.
  • Projeto publicado com GitHub Pages.
  • URL do site funcionando.
  • Site contendo informações do aluno e da disciplina.

  • Links entre as páginas funcionando.
  • Pelo menos dois commits realizados.

13. Entrega

Ao finalizar, entregue ao professor:

  • Nome de usuário do GitHub;
  • Link do repositório;
  • Link do GitHub Pages;
  • Capturas de tela mostrando o repositório;
  • Captura de tela mostrando o GitHub Pages publicado.
Produto final: cada aluno deverá possuir um projeto publicado na Internet e acessível através de uma URL do GitHub Pages.

14. Conceito final

GitHub → Repositório → Arquivos HTML/CSS/JS → GitHub Pages → Site na Internet

A atividade apresenta ao aluno um fluxo real de desenvolvimento e publicação: criar → versionar → publicar → atualizar. Esse processo servirá de base para atividades futuras envolvendo Git, GitHub, desenvolvimento Web, servidores e automação.
