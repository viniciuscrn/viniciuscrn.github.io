Missão 1 · ~25 min

Montar a rede: 3 servidores e 4 clientes

Servidores precisam de endereço fixo: os clientes precisam saber sempre onde encontrá-los. Os clientes, por enquanto, só ficam ligados na rede.

Parte A · Colocar os equipamentos

  • Na barra inferior esquerda, clique em Switches e arraste um 2960 para o centro da área de trabalho.
  • Clique em End Devices e arraste 3 Server-PT (parte de cima) e 4 PC-PT (parte de baixo), como na topologia da Visão geral.
  • Dê nome aos servidores: clique no servidor e vá em Config > GLOBAL > Settings > Display Name. Use SRV-DHCP, SRV-DNS e SRV-WEB. Nomeie também os PCs (PC1 a PC4).

Parte B · Cabeamento

  • Em Connections (ícone do raio), escolha Copper Straight-Through (cabo preto contínuo). Clique no servidor, escolha FastEthernet, depois clique no switch e escolha uma porta FastEthernet0/x livre.
  • Repita para os 3 servidores e os 4 PCs (7 cabos no total). Anote qual porta do switch ficou com cada equipamento.
  • Aguarde as bolinhas dos cabos ficarem verdes. O switch leva alguns segundos; para acelerar, clique várias vezes em Fast Forward Time (barra amarela, canto inferior direito).
Equipamento Porta do equipamento Porta sugerida no switch
SRV-DHCP FastEthernet Fa0/1
SRV-DNS FastEthernet Fa0/2
SRV-WEB FastEthernet Fa0/3
PC1 a PC4 FastEthernet Fa0/11 a Fa0/14

Parte C · IP fixo nos servidores

  • Em cada servidor, abra Desktop > IP Configuration, deixe marcado Static e preencha IP, máscara e DNS conforme a tabela abaixo. Os valores são salvos automaticamente; basta fechar a janela.
  • Confira em Config > INTERFACE > FastEthernet se o IP aparece lá também e se a Port Status está On.
  • Desligue os serviços que não são daquele servidor. Em Config > SERVICES, coloque em Off tudo que não for a função dele. Exemplo: no SRV-DNS, desligue HTTP e DHCP e deixe só DNS. Veja a tabela abaixo.
Servidor IP / Máscara DNS HTTP DHCP DNS (serviço)
SRV-DHCP 192.168.10.10 /24 192.168.10.11 Off On Off
SRV-DNS 192.168.10.11 /24 192.168.10.11 Off Off On
SRV-WEB 192.168.10.12 /24 192.168.10.11 On Off Off
⚠️ Por que desligar os outros serviços?Se dois servidores estiverem com DHCP ligado, os PCs podem receber endereço do servidor errado. É exatamente o problema do "DHCP pirata" numa rede real.

Parte D · Clientes na rede e teste

  • Nos PCs, não configure nada ainda. Eles vão receber endereço na Missão 2, pelo DHCP.
  • Teste a base da rede: no SRV-DHCP, abra Desktop > Command Prompt e faça ping nos outros dois servidores. Os dois precisam responder.
  • Salve o arquivo: File > Save As, com o nome lab-servidores.pkt. Salve de novo ao fim de cada missão. 
SERVER>ping 192.168.10.11
SERVER>ping 192.168.10.12
💡 O primeiro ping falhou?É normal: na 1ª vez o equipamento ainda está descobrindo o MAC do destino (ARP). Repita o comando antes de procurar o erro.

Missão 2 · ~25 min

DHCP: endereço automático para todos

O DHCP entrega aos clientes IP, máscara, gateway e o endereço do servidor DNS.

  • No SRV-DHCP, abra Config > SERVICES > DHCP e marque o serviço como On.
  • Clique no pool serverPool na lista. Os campos são preenchidos com os valores atuais; substitua pelos valores abaixo.
  • Clique em Save e confira se a linha do serverPool na lista mostra os novos valores. ⚠️ Sem salvar, nada muda!
  • Em cada PC, vá em Desktop > IP Configuration e marque DHCP. Aguarde alguns segundos até os campos IP, máscara, gateway e DNS se preencherem sozinhos.
  • No Desktop > Command Prompt de um PC, rode ipconfig /all e confira IP e DNS recebidos. Guarde a saída para o relatório.

Default Gateway192.168.10.1
DNS Server192.168.10.11

PC>ipconfig /all
💡 Como pedir um IP novo ao DHCP no PT 5.0Em IP Configuration, marque Static e depois DHCP de novo. O PC refaz todo o pedido ao servidor. Use esse mesmo truque na simulação do DORA.
⚠️ PC com IP 169.254.x.x?Esse é um endereço APIPA: o PC pediu IP e ninguém respondeu. Verifique se o serviço DHCP está On e se o pool foi salvo.

Missão 3 · ~20 min

DNS: a agenda de contatos da rede

Pessoas lembram nomes, computadores usam números. O DNS faz a tradução.

  • No SRV-DNS, abra Config > SERVICES > DNS e marque DNS Service: On.
  • Em Name, digite www.empresa.local. Em Address, digite 192.168.10.12. Clique em Add; o registro aparece na lista.
  • Adicione um segundo registro: srv-web.empresa.local → 192.168.10.12. Dois nomes podem apontar para o mesmo IP.
  • Em um PC, teste a resolução com nslookup e ping usando o nome. Guarde a saída para o relatório.
Name Address O que significa
www.empresa.local 192.168.10.12 Nome que os usuários digitam no navegador
srv-web.empresa.local 192.168.10.12 Nome técnico do servidor, usado pela equipe de TI
💡 Sobre o tipo de registroNo PT 5.0, o DNS só cria registros do tipo A (nome → IPv4), por isso não aparece a opção de tipo. Em servidores reais, como o Windows Server, existem outros tipos, por exemplo o CNAME, um apelido que aponta para outro nome. 
PC>nslookup www.empresa.local
PC>ping www.empresa.local
⚠️ nslookup não reconhecido?Se o comando não existir nesta instalação, use só o ping www.empresa.local. Se a resposta vier de 192.168.10.12, o nome foi resolvido pelo DNS.
🤔 Pense nissoNinguém configurou o DNS manualmente nos PCs. Mesmo assim eles sabem que devem perguntar ao 192.168.10.11. Quem contou isso a eles?

Missão 4 · ~20 min

HTTP: no ar, o site da empresa

Agora a cadeia se completa: IP pelo DHCP, nome pelo DNS, página pelo HTTP.

  • No SRV-WEB, abra Config > SERVICES > HTTP e confirme que HTTP está On.
  • Na mesma tela aparece uma caixa de texto com o HTML da página padrão (começa com "Welcome to Packet Tracer 5.0…"). Ela é o index.html do servidor.
  • Apague o conteúdo e cole a página da sua empresa (modelo abaixo, personalize os nomes). A alteração vale assim que você digita; feche a janela.
  • Em um PC, abra Desktop > Web Browser e acesse http://www.empresa.local.
  • No Modo Simulação, filtre DNS e HTTP, acesse o site de novo e observe a ordem dos pacotes.
